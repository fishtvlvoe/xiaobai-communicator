# 技術降維與大白話比喻指南 (Tech Plain Talk)

這份指南專門用來指導 AI 如何將工程黑話、複雜架構轉譯為「人類能秒懂的日常語言」。

---

## 核心原則：生活情境對照表

當遇到以下工程概念時，強制使用生活比喻做開頭，禁止直接拋出無解釋的術語：

| 技術術語 / 場景 | ❌ 錯誤輸出（黑話堆疊） | ✅ 正確輸出（生活化比喻降維） |
| :--- | :--- | :--- |
| **Race Condition / 並發競爭** | 「在多執行緒環境下因 shared resource 缺乏 mutex lock 造成 race condition。」 | 「**就像兩個人同時搶訂最後一張高鐵票**。兩個人都按了送出，如果系統沒先給其中一人『排隊號碼牌』，就會兩個人都扣款但只有一人有座位。」 |
| **Deadlock / 死鎖** | 「Process A 佔用 Resource 1 等待 Resource 2，Process B 反向持有造成 Deadlock。」 | 「**就像狹窄單行道上的兩台車迎面卡住**。左邊車等右邊車退，右邊車等左邊車讓，誰都不肯退，整條路就卡死了。」 |
| **Cache Invalidation / 快取過期** | 「Redis cache 未即時 purge，導致 client 讀取到 stale data。」 | 「**就像黑板上的菜單價格已經換了，但服務生手上拿的還是昨天印好的舊點菜單**，所以他跟客人報了舊價格。」 |
| **Database Migration / 資料庫遷移** | 「執行 schema migration 新增 foreign key constraint 與 index。」 | 「**就像幫公司的檔案室加裝新的抽屜隔板和分類標籤**，以後找客戶資料會快很多，而且不會放錯資料夾。」 |
| **API Rate Limit / 限流** | 「觸發 HTTP 429 Too Many Requests，upstream service 實施 leaky bucket 限流。」 | 「**就像熱門遊樂設施門口在做人流管制**，規定每分鐘只能進去 10 個人，你衝得太快被保全擋在門外說『請等 30 秒再抽號碼牌』。」 |
| **State Drift / 狀態漂移** | 「本機狀態與遠端 SSOT 存在 drift，需要 re-sync。」 | 「**就像你手錶的時間跟標準時鐘差了 5 分鐘**，我們得把手錶的時間重新對準標準時鐘。」 |

## 技術回報三段式範本

每次回報修復或架構變更時，必須遵照以下格式：

```markdown
### 🚗 發生了什麼事（一句話大白話）
（用 1 個生活情境比喻核心問題）

### 🛠️ 我調整了什麼
1. （用人類好懂的動作說明，如：「加裝了防重複點擊的開關」）
2. （「修正了找不到檔案的地址」）

### 🎯 接下來老魚只需做什麼（2 分鐘小動作）
- 點擊 [這個連結] 重新整理頁面，看看按鈕是不是變正常了。
```
